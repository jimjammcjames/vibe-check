# mcp-gen-gitignore

## Summary

Ensure mcp-gen outputs that may contain secrets are gitignored by default,
with append-only .gitignore updates and coverage for edge cases.

## Context

mcp-gen writes tool-specific config files for multiple tools. Cursor
configs resolve environment variables into literal values and can
contain secrets if committed. The repo needed a safe default to prevent
accidental commits while keeping merge behavior non-destructive and
preserving existing .gitignore content during repeated runs.

## Error

Secret-bearing files generated by mcp-gen could be committed because
gitignore patterns were not enforced automatically.

## What Changed

- Added append-only .gitignore enforcement for mcp-gen outputs.
- Ensured missing patterns are added without modifying existing content.
- Integrated gitignore enforcement into mcp-gen runtime.
- Added unit and integration coverage for idempotency and preservation.

## Validation

- `npm test` (harness tests) covers new gitignore behavior.
- mcp-gen integration tests verify idempotent .gitignore updates.

## Systemic Gap

We relied on manual gitignore setup for newly generated config files,
which is a common source of secret leaks. The harness had no automated
guardrail to enforce ignore rules at generation time.
Gap Closure: Added test/validation: harness-tests/tests/mcp-gen.test.mjs
and harness-tests/tests/mcp-gen-e2e.test.mjs.

## Class Prevention

Automated, append-only gitignore enforcement eliminates the class of
failures where generator outputs with secrets are committed. This is
now validated by tests to prevent regressions, keep behavior idempotent,
and avoid accidental overwrites in downstream repos.
